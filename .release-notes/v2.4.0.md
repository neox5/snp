# Release v2.4.0

## Overview

v2.4.0 reworks how configuration is resolved. Defaults, `.snpconfig.json` and
the command line are now separate layers that state only what they set, and
later layers win per setting. This fixes several cases where config file
values were ignored, and `--show-config` and `-vv` now show where each value
came from.

## Bug Fixes

### Config file settings are no longer ignored

- `output_path` in `.snpconfig.json` never took effect, because the CLI
  default was always treated as an explicit value. It now wins over the
  default and loses to `--output`.
- Boolean settings in the file (`no_summary`, `no_index`, `no_git_log`,
  `no_content`, `stdout`, `silent`) were overwritten by the CLI even when the
  flag was not given. They now apply unless the CLI says otherwise.
- `--no-index=false` (and the other boolean flags with `=false`) now overrides
  a `true` from the config file.

### `--include=<pattern>` and `--exclude=<pattern>`

The `=` form produced the pattern `=<pattern>`. The pattern is now taken
exactly as typed, including patterns that contain commas such as
`*.{go,md}`.

### `--save-config` writes only what was set

The saved file previously contained the merged result including defaults, the
generation time, the source directory and the dry-run state. It now contains
only settings stated in the existing file or on the command line. Existing
`.snpconfig.json` files load unchanged.
